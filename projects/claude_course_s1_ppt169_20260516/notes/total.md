## P03 Claude 套件有什么不同

先说一下 Claude.ai 这个平台——它现在集成了三个产品：Claude 对话助手、Cowork 自动化工作流，以及 Claude Code 编程工具。今天这节课我们主要围绕这三个产品展开。

那 Claude 套件和其他工具相比有什么真正不同的地方？

**第一个产品：Claude 对话助手。**
核心是两点：超长上下文和精准指令遵循。200k tokens 相当于一次对话可以处理一整本书，这是绝大多数竞品做不到的。而且它的指令遵循非常准——你说要什么格式、什么风格，它就给你什么，不会自作聪明乱发挥。

**第二个产品：Cowork 自动化工作流。**
Cowork 解决的是重复性工作的问题。你设置好流程之后，它会自动持续运行——比如每天自动处理客户询盘邮件、自动生成报表。多个 Agent 可以串联协作，提取信息、分析内容、生成草稿，全程不需要你盯着。

**第三个产品：Claude Code。**
Claude Code 本质上是目前最强大的 AI 编程工具——会写代码的人用它来辅助编程、调试、重构，开发效率可以大幅提升。这个我们有后续的进阶课程会专门深入讲，如果你是开发者，那绝对值得期待。

但就算你完全不会写代码，Claude Code 对你一样非常有用。它有非常丰富的 Skills 系统——可以安装现成的 Skill，比如 superpowers 和 ppt-master；还可以自己定制专属 Skill，让 Claude Code 变成针对你工作场景的专家。这两个我们后续课程会专门介绍，非常强大。

所以 Claude Code 不只是"程序员的工具"，它是一个可以无限扩展能力的平台，会写代码和不会写代码的人都能从中受益。

## P04 Claude 能做什么

Claude 能做的事情其实非常广——

写作润色：无论是邮件、报告、社交媒体文章，给它背景和要求，它可以生成高质量的初稿。

## P09 最常见的错误用法

先来看左边的错误用法。

"帮我写封邮件"——这样说 AI 会懵，因为它不知道写给谁、什么语气、什么目的，只能给你一个平庸的模板。

"第一条回复不好就放弃"——这是把 AI 当成一次性工具，而不是一个可以迭代的工作流程。

"AI 说什么我就用什么"——这是最危险的，你放弃了自己的判断力。

右边是正确的做法：给完整的背景和要求；把 AI 的回复当成草稿来迭代；最终决策永远是你的。

---

## P10 协作三原则

把正确的用法总结成三条原则：

第一：给上下文。告诉 AI 你是谁、任务背景是什么、你期望的格式是什么。背景给得越多，输出质量越高——这不是夸张，经过验证可以提高 3 倍以上的质量。

第二：迭代而非追求一次完美。第一条回复是草稿，你告诉它哪里不好、怎么改，反复几轮就能到满意的结果。

第三：你负责判断。AI 提供选项和素材，最终决策是你的。AI 是助理，不是老板。

---

## P11 Projects：让 Claude 记住你

前面说了给上下文的重要性，每次都要重新介绍背景太麻烦了——这时候 Projects 就是解决方案。

在 Claude 里，你可以创建一个 Project，写入你的角色、偏好、行业背景——比如"我是一个外贸公司的市场经理，主要处理英语客户询盘，语气要专业但不失亲切"。

写进去一次，之后每次在这个 Project 里开始对话，Claude 就自动知道这些背景了。

这样你就彻底告别每次重新自我介绍的麻烦，Claude 真正变成你的专属助理。

## P13 从 Claude.ai 到 Cowork

在演示之前，先解释一下 Claude.ai 和 Cowork 的区别。

左边的 Claude.ai 是我们刚才用的方式——对话式，适合一次性的任务，比如写一封邮件、分析一个文档。

右边的 Cowork 是什么？它是一个基于 Claude 的自动化工作流工具，适合那些规律性、重复性的工作——比如每天都要处理的询盘邮件、每周要生成的报表。

从 Claude.ai 到 Cowork 是一个升级——从"手动做"到"自动化"。

---

## P14 Cowork 是什么

Cowork 的工作方式是这样的，四个步骤：

第一步：定义触发条件。什么时候开始？可以是收到一封邮件、也可以是每天定时启动、或者手动点击触发。

第二步：设置 AI 处理流程。这里你定义 AI 要做什么——比如提取邮件关键信息、分析客户需求、然后生成回复草稿。多个步骤串联成一个 Agent 链。

第三步：Claude 自动执行。你设好流程后，Claude 会自动按步骤完成每一个 Agent 的任务，不需要你一步一步手动操作。

第四步：结果输出。你得到的是可以直接用的成品——回复草稿、分析报告、或者通知消息。
